调用此 skill 时：

1. **完整阅读目标文件**。

2. **阅读 CLAUDE.md** 中的项目编码标准。

3. **识别系统类别**（引擎、游戏性、AI、网络、UI、工具）并应用类别特定标准。

4. **对照编码标准评估**：
   - [ ] 公共方法和类有文档注释
   - [ ] 每个方法的圈复杂度低于 10
   - [ ] 无方法超过 40 行（不包括数据声明）
   - [ ] 依赖通过注入提供（游戏状态不使用静态单例）
   - [ ] 配置值从数据文件加载
   - [ ] 系统暴露接口（而非对具体类的依赖）

5. **检查架构合规性**：
   - [ ] 正确的依赖方向（引擎 <- 游戏性，非反向）
   - [ ] 模块间无循环依赖
   - [ ] 适当的层分离（UI 不持有游戏状态）
   - [ ] 跨系统通信使用事件/信号
   - [ ] 与代码库中已建立的模式一致

6. **检查 SOLID 合规性**：
   - [ ] 单一职责：每个类只有一个变更原因
   - [ ] 开闭原则：可扩展而无需修改
   - [ ] 里氏替换：子类型可替换基类型
   - [ ] 接口隔离：无臃肿接口
   - [ ] 依赖倒置：依赖抽象而非具体

7. **检查常见游戏开发问题**：
   - [ ] 帧率无关（使用 delta time）
   - [ ] 热路径中无分配（update 循环）
   - [ ] 适当的 null/空状态处理
   - [ ] 需要时线程安全
   - [ ] 资源清理（无泄漏）

8. **输出评审**，格式如下：

```
## 代码审查：[文件/系统名称]

### 标准合规：[X/6 通过]
[列出失败项及行号引用]

### 架构：[清晰 / 小问题 / 发现违规]
[列出具体的架构关注点]

### SOLID：[合规 / 发现问题]
[列出具体的违规项]

### 游戏特定关注点
[列出游戏开发特定问题]

### 正面观察
[做得好的地方——始终包含此部分]

### 必须变更
[批准前必须修复的项]

### 建议
[锦上添花的改进]

### 结论：[批准 / 批准含建议 / 需要变更]
```
